# 工作單生命週期

> English: [../work-order-lifecycle.md](../work-order-lifecycle.md)

工作單是人類核准的任務界線，不是模型取得授權的來源。執行環境必須另行驗證身分與權限。

## 狀態

`draft → submitted → approved → running → completed`

可在任何執行前階段標記為 `rejected` 或 `cancelled`；執行開始後可轉為 `failed`、`cancelled` 或 `needs_review`。狀態轉換須保留時間、操作者或服務身分，以及原因。

## 流程

1. **建立**：請求者填寫目的、範圍、輸入資料、允許工具、禁止動作、驗收條件、有效期限及負責人。
2. **預檢**：系統驗證必填欄位、身分、權限、政策版本及風險分類。未通過時不得開始執行。
3. **核准**：具適當職責的人員依風險審查。核准須綁定工作單版本；任何實質變更都應重新核准。
4. **執行**：環境依核准範圍提供受限權限。每次工具呼叫均應由環境驗證，不得只採信代理文字。
5. **停止或升級**：遇到超出範圍、資料不足、政策衝突、風險升高、核准失效或安全疑慮時，停止副作用並轉交負責人。
6. **驗收與結案**：依事先定義的條件核對結果；將成功、部分完成及失敗分開記錄，不以代理自述作為唯一證據。由誰查驗、由誰放行，見[品質閘門](quality-gates.md#三個審查席位)。
7. **檢視與改善**：依工作流程風險抽樣檢查收據與結果，必要時暫停該工作流程、撤銷權限或更新政策。

## 核准與撤銷

核准需有範圍、有效期限及核准者。若工作單已修改、身分或權限變更、政策更新與原核准內容不相容，或風險假設不再成立，應使核准失效。若政策更新並未改變這張工作單被允許做的事，就不應讓進行中的工作作廢：在工作單上註記新的政策版本後繼續進行（見「政策更新與進行中的工作」）。撤銷後，執行環境應阻止新動作；對已開始的動作則依預定停止與復原程序處理。

## 失敗處理

失敗不可偽裝成成功。記錄已完成與未完成的步驟、可能副作用、補救狀態及負責人。重試須受次數與冪等性限制；無法安全重試時轉人工處理。

## 先分類：什麼時候需要工作單

這是第一件要決定的事，因為它決定一個請求該走多少流程。

- **不需要工作單**：讀取、搜尋、回答問題，或只留在對話裡的計畫。這些沒有外部影響，審查它們只會增加等待，不會降低風險。
- **需要工作單**：凡是用工具去改動檔案、設定、部署或外部系統，或把東西送給另一方。把計畫存成文件也算改動。

為什麼界線畫在這裡：審查的力氣有限。把它花在無害的讀取上，會讓人把審查當成雜訊；只留給有後果的動作，審查才有意義。分不清楚時，一律當成需要工作單。

## 自動化作業走同一條生命週期

會改動生產環境的排程或流程，跟任何執行者一樣，不該有一條繞過審查的私人通道。

- 為每一項自動化作業準備**預先核准的任務清單**：它做什麼、可以碰哪些資源、正常結果長什麼樣。清單審查一次，內容有改再審。
- 每次執行後，拿結果跟任務清單比對。相符的進入放行；不相符的（數值超出預期範圍、碰到清單外的資源、結構不同）就是**異樣**：先停下來，交給指定的協調者處理，處理完才能放行。
- 自動化作業不得自行把產出排進放行佇列。

## 不留孤兒工作單

執行者已經停下來的工作單（工作階段關閉、憑證過期、停在閘門前沒人看），仍然是某個人做過的承諾。

- 每一張未結案的工作單，任何時候都只有一位現任負責人，而且查得到是誰。
- 設定從計畫核准起算的期限。工作單停滯或逾期時，改派給協調者；協調者只能交接給另一位執行者，或自己完成，不能擱著。
- 追蹤「找不到負責人的未結案工作單」數量。目標是零；不是零這件事本身就該觸發告警。

## 取消也要留下紀錄

取消是一個決定，決定就需要證據。`cancelled` 的工作單跟 `completed` 的一樣要有結案紀錄：誰取消、為什麼、已經做了哪些、由什麼取代或放棄。如果取消是因為做錯，要把那個錯誤記下來（見[收據與稽核紀錄](receipts-and-audit.md#事故紀錄與重犯防護)）。取消要經過負責結案的同一個放行席位，「取消」才不會變成逃避審查的方法。

## 政策更新與進行中的工作

工作進行到一半，政策可能會改。事先決定政策更新對未結案工作單的影響，並讓執行環境照這個決定運作。

- 更新沒有改變某張工作單被允許做的事：在工作單上註記新的政策版本，繼續進行。
- 有改變：撤銷核准，要求重新核准。
- 不要讓一次更新同時悄悄作廢所有未結案的核准。那會把例行的政策調整，變成審查流程自己的停擺。
