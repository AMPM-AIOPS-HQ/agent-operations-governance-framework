# 品質閘門

> English: [../quality-gates.md](../quality-gates.md)

品質閘門是實際執行控制，不是只供代理參考的建議文字。每道閘門應記錄判定結果、政策版本及失敗處置。

| 閘門 | 最低檢查 | 未通過時 |
| --- | --- | --- |
| 任務完整性 | 目的、負責人、範圍、停止條件、驗收條件與期限存在 | 拒絕提交 |
| 身分與授權 | 請求者、核准者及執行身分有效；權限符合工作單 | 拒絕或升級 |
| 資料處理 | 資料來源、敏感度及允許用途明確；秘密不進入一般紀錄 | 隔離資料並停止 |
| 工具限制 | 僅可呼叫明確允許的工具與操作；限制副作用及資源使用 | 阻擋呼叫 |
| 高影響動作 | 刪除、外部發布、付款、權限變更等依政策取得人工核准 | 暫停等待核准 |
| 執行安全 | 逾時、重試、限流及中止機制已設定 | 終止或轉人工 |
| 結果驗收 | 以獨立於代理自述的檢查比對預定條件 | 標記未驗收 |
| 結案紀錄 | 產生最少必要的收據，標示失敗、部分完成及核准狀態 | 不得標記完成 |

## 測試最低要求

在試行前，至少測試：

- 缺欄位、無效身分、過期核准及工作單修改後的舊核准。
- 超出範圍的工具要求、拒絕、逾時、重複請求及部分失敗。
- 外部內容帶有指令、敏感資料外洩風險，以及必須升級人工的情境。
- 人工取消、權限撤銷、重試上限與復原程序。

測試結果僅適用於明確記錄的環境、版本、資料與情境。模擬測試不能代表生產環境表現、錯誤率保證或認證。

## 三個審查席位

上面八道閘門說的是「查什麼」。這一節說的是「誰來查」，因為由被查的人自己查，不算查。

| 席位 | 時間點 | 職責 | 負責的閘門 |
| --- | --- | --- | --- |
| 計畫審查 | 執行前 | 計畫是否完整？驗收條件是否可以實際檢驗？清單裡是否至少有一條反例，也就是「如果做錯了，哪一項檢查應該失敗」？ | 任務完整性；身分與授權 |
| 結果查驗 | 執行後 | 獨立重跑每一項驗收與反例。執行者自己的報告只是輸入，不是證據。 | 結果驗收 |
| 放行與結案 | 查驗後 | 確認前兩個席位都留下紀錄，然後親自執行放行，在正式環境觀察結果，並簽發收據。 | 高影響動作；結案紀錄 |

其餘閘門（資料處理、工具限制、執行安全）由執行環境持續強制，不屬於任何席位。

這三個席位值得設立，是因為它們具備三個性質：

- **分離**：席位不得由被審查的執行者擔任；席位也不審查另一個席位的判定。
- **誰放行，誰執行**：核准放行的席位，就是實際執行放行的席位，而且一次只放行一張工作單。如果核准與放行是兩個不同的人做的兩個步驟，沒審過的工作就會從中間的縫隙混進去。一次只放行一張，也代表一件有問題的工作不會拖住後面排隊的全部。
- **沒有收據，就不能說完成**：放行席位簽發收據之前，任何人都不得把這件工作描述為完成。

## 閘門本身也要可靠

閘門是軟體加流程，會像其他東西一樣出錯。設計時要把這件事算進去。

- **說清楚怎樣才會過。** 閘門退回時，要講明補上什麼證據就能改變判定。閘門不得要求一個根本無法提供的東西。
- **卡住就要升級。** 閘門對同一張工作單反覆停下，或自己根本跑不起來時，要通知人。每分鐘在日誌寫同一行不算升級。
- **隔離壞輸入。** 一張格式損壞的工作單，不得讓閘門停止處理其他工作單。跳過它、標記它、繼續。
- **規則要公開。** 閘門執行的每一條規則，都要寫在執行者送審前讀得到的地方。只能靠被退件才發現的規則，會浪費所有人的時間，還會教執行者用猜的。
- **同一套規則。** 兩道閘門查同一件事，就共用同一份定義。同一條規則寫兩份，遲早會走樣並互相矛盾。

## 用 AI 模型當審查員

模型讀得懂送審內容，能注意到固定規則會漏掉的東西。它也可能前後不一致，也可能被說服。照這個特性去用它。

- 過不過由確定性的檢查決定。模型可以提出**疑點**，但不握有判定權。
- 每一個疑點都必須是答得了的：它要指出哪一項證據可以解決它。
- 限制往返的輪數；解決不了的交給人，不要讓它一直擋著。
- 審查員也要被評估。記錄哪些疑點有道理、哪些沒有，據此調整給它的指示。

## 格式檢查與事實檢查

對回報的「寫法」加檢查很容易：必填的標頭、必寫的句子、引用的格式。每一條單獨看都很便宜。加在一起，花的力氣可能超過查證事實本身，而且執行者會學會滿足格式而不是實質。優先採用能驗證工作本身是否屬實的檢查，並定期檢視格式檢查，拿掉那些已經不值得的。
